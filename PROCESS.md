# Process

The brief asks for an app that's multi-user, real-time, and persistent, with its own defensible definition of "good." Before any server code existed, `planning.md` [1c700a4](https://github.com/comp4020-agentic-coding-studio/comp4020-final-brendanmeyer/commit/1c700a4) answered multi-user with a mechanic rather than a session layer: no player steers the snake directly, every active cursor pulls it toward the centroid of everyone active, each weighted exactly `1/n`, so "the game cannot meaningfully be played alone." That document went through two further passes before a line of code existed - pinning the scoring multiplier to a concrete, increasing-returns formula instead of a vague "gradual" placeholder, then adding identity, queueing, and replay as subsystems the first draft only gestured at [5aa3629](https://github.com/comp4020-agentic-coding-studio/comp4020-final-brendanmeyer/commit/5aa3629) [7bf1793](https://github.com/comp4020-agentic-coding-studio/comp4020-final-brendanmeyer/commit/7bf1793) - on the view that a well-thought-out base is worth having before a build starts, not something to discover mid-implementation.

## Splitting research from planning, and planning from coding

Before `planning.md` [1c700a4](https://github.com/comp4020-agentic-coding-studio/comp4020-final-brendanmeyer/commit/1c700a4) was written, three separate AI tools (Claude, ChatGPT, and Qwen) were each given the brief and the course template and asked to research and plan independently, rather than researching and planning inside one running conversation with one tool. Comparing the three outputs caught things a single uninterrupted pass would likely have missed - one surfaced that Node's built-in SQLite module needed its actual stability status checked rather than assumed from training data, which is exactly the caveat that later shaped the `node:sqlite`-over-`better-sqlite3` decision below. The same separation held within a single tool afterward: a dedicated research phase, then a dedicated planning phase, each starting without the other's assumptions already baked in, rather than one pass that researches and designs at the same time and risks anchoring on whatever idea came first.

## Scoping discipline, repeated every crit

`planning.md`'s full design was never the whole build for any one week. `CLAUDE.md` and `README.md` stated, before code existed, exactly what each slice commits to - crit 8's centroid steering and two-player minimum [eef072d](https://github.com/comp4020-agentic-coding-studio/comp4020-final-brendanmeyer/commit/eef072d), later crits' own named scope - and `spec/*.test.ts` were written and confirmed red against that scope before the server did [bd39395](https://github.com/comp4020-agentic-coding-studio/comp4020-final-brendanmeyer/commit/bd39395), a pattern every later feature in this repo repeats rather than departs from. Deferral was deliberate, not an oversight: crit 8 named the disconnect/queue/colour system `planning.md` specified and left it explicitly unbuilt, documented rather than silently dropped.

## The stack, and why it held under a growing scope

Node's built-in `node:sqlite` module was chosen over `better-sqlite3` [4398aa1](https://github.com/comp4020-agentic-coding-studio/comp4020-final-brendanmeyer/commit/4398aa1): the one Fly machine has no separate database server, and a native driver would need a node-gyp build step in the image for a single dependency. The trade-off was accepted openly - Node's own docs still mark the module a release candidate - and mitigated by sticking to its narrowest, longest-settled surface. The server runs its TypeScript source directly with no build step [7b1bb70](https://github.com/comp4020-agentic-coding-studio/comp4020-final-brendanmeyer/commit/7b1bb70): a handful of routes and one WebSocket upgrade don't justify a framework's routing abstraction. That connection is a WebSocket specifically, not polling or server-sent events, because proving two sessions' input converges into one steered snake needs a bidirectional, low-latency channel neither can give [1b232b0](https://github.com/comp4020-agentic-coding-studio/comp4020-final-brendanmeyer/commit/1b232b0). The client alone keeps a real build step, since browsers don't strip types, but stays vanilla canvas rather than a framework - a few draw calls a tick and no DOM tree to diff don't earn one [b890564](https://github.com/comp4020-agentic-coding-studio/comp4020-final-brendanmeyer/commit/b890564).

These choices were tested by scale, not just asserted once. Colours, disconnect handling, a 12-player cap, a FIFO queue, leaderboard ties, and ghost-trail replay all landed as separate phases [7cd8acd](https://github.com/comp4020-agentic-coding-studio/comp4020-final-brendanmeyer/commit/7cd8acd) [796a0cf](https://github.com/comp4020-agentic-coding-studio/comp4020-final-brendanmeyer/commit/796a0cf) [dd5b5ad](https://github.com/comp4020-agentic-coding-studio/comp4020-final-brendanmeyer/commit/dd5b5ad) without the build-free server or the framework-free client needing to change shape. Requested all at once rather than piecemeal, that expansion went through research-then-planning before a line was written - two parallel passes over the existing code and design text, then eight sequenced phases ordered so stopping at any boundary left a complete, working slice [6b35d3e](https://github.com/comp4020-agentic-coding-studio/comp4020-final-brendanmeyer/commit/6b35d3e). The stack's real limit showed in schema migration: the production `runs` table had existed since crit 8, so `CREATE TABLE IF NOT EXISTS` does nothing to it - new columns needed real, idempotent `ALTER TABLE` statements, proven against a copy of the deployed schema before shipping, since neither CI nor local `pnpm check` starts from anything but an empty database [693161a](https://github.com/comp4020-agentic-coding-studio/comp4020-final-brendanmeyer/commit/693161a).

## Identity and permissions, written down rather than assumed

A second browser tab sharing `localStorage` silently became a second connection for the same player, letting one visitor inflate the group-size scoring multiplier `README.md` calls real rather than decorative. The server now offers a confirmed takeover instead of silently doubling up or kicking a connection [103aec3](https://github.com/comp4020-agentic-coding-studio/comp4020-final-brendanmeyer/commit/103aec3), with the rejected alternatives written into `decisions/0001` against the same explains-itself bar the README sets. A later spec asked directly what each person may see or change, checked server-side and written down why: auditing the existing protocol mattered more than writing new code, since no message the server accepts can even name another player - every handler already only ever acts on its own sender, by construction [193d03b](https://github.com/comp4020-agentic-coding-studio/comp4020-final-brendanmeyer/commit/193d03b). The audit log that spec asked for was built the usual way - a failing spec for its shape first [dcac976](https://github.com/comp4020-agentic-coding-studio/comp4020-final-brendanmeyer/commit/dcac976), then a persistent table wired into every identity, queue, role, and scoring change the server makes [b841d4a](https://github.com/comp4020-agentic-coding-studio/comp4020-final-brendanmeyer/commit/b841d4a).

## Real bugs came from running the app, not from green tests

A pre-crit-9 preflight ran the full spec suite against the deployed URL, not CI's throwaway container, and found failures nothing local had caught - latency margin problems, and a genuine production bug where a historical record score existed but never surfaced in the records list, left documented rather than patched blind. Manually playing the live app surfaced three more: a CSS specificity bug that made Play do nothing visibly, a name field that silently never adopted a typed value over a stored pseudonym, and a confirm dialog breaking the game's own visual frame - none caught by a passing suite, all found by using the thing a stranger would use. A later, directly reported bug fit the same pattern: password-based retrieval silently failed whenever a browser already held any unrelated stored token, since the server checked that token before ever checking a proven password [1681e5d](https://github.com/comp4020-agentic-coding-studio/comp4020-final-brendanmeyer/commit/1681e5d) [44874ea](https://github.com/comp4020-agentic-coding-studio/comp4020-final-brendanmeyer/commit/44874ea) - reproduced against a running server before any test was written, because every existing test used a fresh client with no leftover state, unlike a real returning visitor.

The throughline across all three crits is the same loop, not three different processes: state a bar in `CLAUDE.md` before code exists, write a failing test against it, build the smallest thing that turns it green, then check the result against the actual deployed app rather than trusting the suite alone.
