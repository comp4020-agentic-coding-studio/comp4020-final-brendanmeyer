# Process

## Crit 8

The full design came first [1c700a4](https://github.com/comp4020-agentic-coding-studio/comp4020-final-brendanmeyer/commit/1c700a4) for a cooperative Snake where no one player steers directly, every active player's cursor instead pulling toward a shared centroid.

The scope and acceptance bar for this build were written next [eef072d](https://github.com/comp4020-agentic-coding-studio/comp4020-final-brendanmeyer/commit/eef072d) [0ec4f0c](https://github.com/comp4020-agentic-coding-studio/comp4020-final-brendanmeyer/commit/0ec4f0c), stating before any server code existed exactly what this build commits to: real centroid steering, scoring between two active sessions, a persisted per-visitor artifact, and the 2-player minimum held from the first commit with a game loop. Checks were written against that scope next [bd39395](https://github.com/comp4020-agentic-coding-studio/comp4020-final-brendanmeyer/commit/bd39395), before the server existed, and confirmed red before anything was built.

The stack followed from there. node + sqlite was chosen over a native driver such as better-sqlite3 [4398aa1](https://github.com/comp4020-agentic-coding-studio/comp4020-final-brendanmeyer/commit/4398aa1), since the single Fly machine has no separate database server. The server runs straight from its own source with no separate build step [7b1bb70](https://github.com/comp4020-agentic-coding-studio/comp4020-final-brendanmeyer/commit/7b1bb70) [1a421e8](https://github.com/comp4020-agentic-coding-studio/comp4020-final-brendanmeyer/commit/1a421e8), since it's only a handful of pages plus one live connection kept open between the two browsers — a connection chosen over something that just checks in every so often, because proving two people's movements blend into one shared snake needs updates flowing both ways immediately, without delay. The one part that does need to be built before it can run is what shows up in the browser itself [b890564](https://github.com/comp4020-agentic-coding-studio/comp4020-final-brendanmeyer/commit/b890564), and that was kept as plain, simple code rather than reaching for a framework - at this time there is not enough happening on screen at once to justify one.

A manual two-session run confirmed the whole stack end to end [1b232b0](https://github.com/comp4020-agentic-coding-studio/comp4020-final-brendanmeyer/commit/1b232b0), waiting at one player, running at two, score rising correctly as food is eaten, and a collision finalising a run that was then handed back correctly to that specific player afterwards.

## Crit 9

Testing the deployed application revealed misleading multi-window instructions and limited mobile screen space. These were addressed through clearer instructions, fullscreen functionality, and server-side duplicate-connection handling with takeover confirmation [fb6f01d](https://github.com/comp4020-agentic-coding-studio/comp4020-final-brendanmeyer/commit/fb6f01d8e919efa13f58829f50cf660e83e56475), [01dec80](https://github.com/comp4020-agentic-coding-studio/comp4020-final-brendanmeyer/commit/01dec80a7daf3dde8c7263f29ceda6948d9f53c9), [103aec3](https://github.com/comp4020-agentic-coding-studio/comp4020-final-brendanmeyer/commit/103aec3c9f872341fd9bbc032b821cbec5f4a4bb).

Development expanded into eight test-driven phases covering player colours, disconnect detection, mid-game joining, a 12-player capacity, spectators, FIFO queuing, leaderboard statistics, and record-run ghost trails [7cd8acd](https://github.com/comp4020-agentic-coding-studio/comp4020-final-brendanmeyer/commit/7cd8acd), [5adb45c](https://github.com/comp4020-agentic-coding-studio/comp4020-final-brendanmeyer/commit/5adb45c), [bd37a92](https://github.com/comp4020-agentic-coding-studio/comp4020-final-brendanmeyer/commit/bd37a92), [6de50d0](https://github.com/comp4020-agentic-coding-studio/comp4020-final-brendanmeyer/commit/6de50d0), [796a0cf](https://github.com/comp4020-agentic-coding-studio/comp4020-final-brendanmeyer/commit/796a0cf), [1e1549b](https://github.com/comp4020-agentic-coding-studio/comp4020-final-brendanmeyer/commit/1e1549b), [dd5b5ad](https://github.com/comp4020-agentic-coding-studio/comp4020-final-brendanmeyer/commit/dd5b5ad).

WebSockets broadcast game state in real time, while historical statistics may require refreshing. Players identify others through coloured cursors and join/leave animations; spectators observe without cursors. Multiple players can interact simultaneously, as the server processes inputs and maintains a single authoritative game state broadcast to everyone [4142aaf](https://github.com/comp4020-agentic-coding-studio/comp4020-final-brendanmeyer/commit/4142aaf).

Reconnecting within five seconds allows players to continue their session. Otherwise, they rejoin normally or enter the spectator queue when capacity is reached. Returning the next day follows the normal joining process, with players entering the queue if the game is full. Duplicate identities are prevented through connection takeover handling [103aec3](https://github.com/comp4020-agentic-coding-studio/comp4020-final-brendanmeyer/commit/103aec3c9f872341fd9bbc032b821cbec5f4a4bb), [796a0cf](https://github.com/comp4020-agentic-coding-studio/comp4020-final-brendanmeyer/commit/796a0cf).

A significant challenge involved migrating existing production database tables. Idempotent migrations were tested against existing schemas, protecting historical records [693161a](https://github.com/comp4020-agentic-coding-studio/comp4020-final-brendanmeyer/commit/693161a).

The client interface exposed these features through colour selection, animations, queue controls, and statistics. Deployment verified preserved historical data and functioning real-time communication [038bdda](https://github.com/comp4020-agentic-coding-studio/comp4020-final-brendanmeyer/commit/038bdda).

Overall, this reinforced the importance of test-first development, incremental delivery, server-authoritative multiplayer design, and production validation.

## Crit 10

The published brief asked for the app to stay multi-user and deployed, for what each person can see or change to be checked on the server and written down with a reason, and for the app to log who did what in a way that survives past the crit itself [f21d237](https://github.com/comp4020-agentic-coding-studio/comp4020-final-brendanmeyer/commit/f21d237).

Checking what the protocol already allowed came first. No message a client can send names another player at all, so every handler already only ever acts on the sender's own identity; this was written up as a decision rather than treated as something needing new code [193d03b](https://github.com/comp4020-agentic-coding-studio/comp4020-final-brendanmeyer/commit/193d03b). The audit log itself was built test-first: a failing spec for the logging shape came before any logging code [dcac976](https://github.com/comp4020-agentic-coding-studio/comp4020-final-brendanmeyer/commit/dcac976), then a persistent events table and a helper that both prints a line and saves it [ba3f30d](https://github.com/comp4020-agentic-coding-studio/comp4020-final-brendanmeyer/commit/ba3f30d), then that helper wired into every identity, queue, role, and scoring change the server makes [b841d4a](https://github.com/comp4020-agentic-coding-studio/comp4020-final-brendanmeyer/commit/b841d4a). A later addition logs every active player's position on a fifteen-second timer while a game runs, not just when something happens, so a presenter narrating from the logs always has something current to point at [aacd674](https://github.com/comp4020-agentic-coding-studio/comp4020-final-brendanmeyer/commit/aacd674) [0935c91](https://github.com/comp4020-agentic-coding-studio/comp4020-final-brendanmeyer/commit/0935c91) [8d99651](https://github.com/comp4020-agentic-coding-studio/comp4020-final-brendanmeyer/commit/8d99651).

A real bug surfaced outside the planned work: a visitor whose browser already held any reconnect token could never retrieve a different, password-protected name, correct password or not, because the server checked that token before ever checking a proven password. The failing case was written first [1681e5d](https://github.com/comp4020-agentic-coding-studio/comp4020-final-brendanmeyer/commit/1681e5d), then fixed by checking a correctly-proven password before falling back to the token [44874ea](https://github.com/comp4020-agentic-coding-studio/comp4020-final-brendanmeyer/commit/44874ea). The password flow was rounded out from there: the server now says whether an identity already has a password, letting a name claimed without one add one later behind a themed dialog in the game's own frame rather than a native browser prompt [811fb15](https://github.com/comp4020-agentic-coding-studio/comp4020-final-brendanmeyer/commit/811fb15) [9d010da](https://github.com/comp4020-agentic-coding-studio/comp4020-final-brendanmeyer/commit/9d010da), and the same flag hides the entry screen's password field once a browser already holds a token, paired with a "Change user" button to leave an identity deliberately instead [f289ff4](https://github.com/comp4020-agentic-coding-studio/comp4020-final-brendanmeyer/commit/f289ff4) [4248b6d](https://github.com/comp4020-agentic-coding-studio/comp4020-final-brendanmeyer/commit/4248b6d).

A separate pass checked the shipped build against the original design document, not any one crit's scope, and found three real gaps: the centroid was computed every tick but never sent to the browser, every pickup always grew the snake instead of randomly choosing to grow or speed up, and only one food item could ever exist at once. All three were closed test-first: the centroid now reaches the browser, toggled by a key and off by default [6842c67](https://github.com/comp4020-agentic-coding-studio/comp4020-final-brendanmeyer/commit/6842c67) [9013510](https://github.com/comp4020-agentic-coding-studio/comp4020-final-brendanmeyer/commit/9013510); each pickup now rolls one of the two bonuses at random, never both [6d2aff2](https://github.com/comp4020-agentic-coding-studio/comp4020-final-brendanmeyer/commit/6d2aff2); the board can now hold more than one food item, weighted toward fewer [4645147](https://github.com/comp4020-agentic-coding-studio/comp4020-final-brendanmeyer/commit/4645147). The page showing global stats and record replays was also rebuilt as a dialog over the game instead of a separate page [7c3bdce](https://github.com/comp4020-agentic-coding-studio/comp4020-final-brendanmeyer/commit/7c3bdce), alongside a help dialog listing every keyboard shortcut the app now has [7666fb7](https://github.com/comp4020-agentic-coding-studio/comp4020-final-brendanmeyer/commit/7666fb7).

Checking the live app against the brief's demo format mattered as much as building any one feature: two independent browser sessions needed to look obviously like two different people on screen, and the logs needed to actually read as a story a presenter could narrate live, not just exist. Both were confirmed directly against the deployed app, with the server's own log output tailed in real time against real sessions, not inferred from the tests alone.
